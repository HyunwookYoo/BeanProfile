사진 OCR 신뢰성 개선 — 설계

상태: 구현 완료, 실기기 검증 대기. 구현 계획: photo-ocr-reliability-plan.md.

1. 배경

현재 사진 입력은 image_picker가 반환한 사진을 ML Kit에 한 번 전달하고, 좌표 기반 파서가 하나의 원산지 구성만 포함한 OcrDraft를 만든다. 폼은 OCR 입력에서도 싱글 오리진으로 시작한다.

실사용에서 다음 문제가 확인됐다.

  • 카드에 Blend/블렌드가 명시된 경우와, 명시 없이 원산지 구성이 여러 개 나열된 경우가 혼재한다.
  • 현재 초안은 원두 유형과 복수 원산지 구성을 표현하지 못해 블렌드를 싱글로 열고, 인식한 정보도 첫 구성에 몰린다.
  • 어두운 배경의 저대비 글자는 일부 또는 대부분이 누락된다.
  • 빛 반사·그림자·초점 흐림이 섞인 사진은 후처리만으로 복구할 수 없는 경우가 있다.
  • 촬영 이미지는 OCR 전에 JPEG 품질 85로 반환돼, 작은 글자 정보가 추가로 손실될 여지가 있다.

기존 M3.3의 좌표 기반 라벨↔값 매칭, 콜론/키워드 폴백, 칩 배정 UX는 유지한다. 이번 작업은 그 위에 사진 품질 계층, 조건부 재인식, 유형 추론, 복수 구성 초안을 추가한다.

2. 목표와 비목표

목표

  • 확실한 싱글/블렌드는 사용자 질문 없이 올바른 유형으로 폼을 연다.
  • 유형 단서가 없거나 충돌하면 한 번만 사용자에게 확인한다.
  • 블렌드의 국가·지역·가공·비율을 구성별로 분리해 폼에 배치한다.
  • 저대비 사진은 OCR용 보정 사본으로 한 번 더 인식해 원본보다 나은 결과를 선택한다.
  • 반사·흐림 등 복구가 어려운 사진은 재촬영을 권하되 진행을 막지 않는다.
  • 분석·보정·두 번째 OCR이 실패해도 원본 OCR 또는 수동 입력으로 안전하게 폴백한다.

비목표

  • 실시간 카메라 프리뷰 분석이나 문서 테두리 자동 촬영은 포함하지 않는다.
  • 서버 OCR, 외부 커피 카탈로그, 원격 모델은 사용하지 않는다.
  • OCR이 카드에 없는 구성 정보를 추측하거나 생성하지 않는다.
  • 모든 브랜드의 자유형 봉투 레이아웃을 완전 자동화하지 않는다.
  • 촬영 사진을 흑백 보정본으로 교체하지 않는다.

3. 승인된 사용자 흐름

  1. 사용자가 촬영하거나 갤러리에서 사진을 고른다.
  2. 사진 품질을 분석하고 컬러 원본으로 첫 OCR을 수행한다.
  3. 저대비이거나 첫 결과가 약하면 보정 사본으로 두 번째 OCR을 수행한다.
  4. 두 결과를 비교해 주 결과를 고르고, 충돌하지 않는 빈 필드만 보완한다.
  5. 두 결과가 모두 약하고 사진 품질에도 문제가 있으면 다시 촬영과 인식 결과로 계속을 제시한다.
  6. 계속 진행한 결과에서 원두 유형을 추론한다.
  7. 유형이 확실하면 묻지 않고 폼을 연다.
  8. 유형 단서가 없거나 충돌하면 싱글 오리진 / 블렌드를 한 번 확인한다.
  9. 유형에 맞는 원산지 구성 목록을 폼에 채운다.
  10. 블렌드 구성 정보가 2개 미만이어도 경고 후 저장을 허용한다.

재촬영 권고와 유형 확인이 모두 필요하면 재촬영 권고를 먼저 표시한다. 재촬영으로 OCR 결과와 유형이 모두 달라질 수 있기 때문이다.

4. 구조와 책임

기존 PhotoService, OcrService, 순수 Dart 파서, 폼의 경계를 유지하고 다음 단위를 추가한다.

단위책임의존성
ImageQualityAnalyzer사진을 축소해 저대비·흐림·강한 하이라이트 지표 산출image
OcrImagePreprocessorOCR용 회색조·히스토그램·대비 보정 임시 PNG 생성 및 정리image, 임시 디렉터리
OcrPipeline원본 OCR, 조건부 보정 OCR, 결과 순위 결정, 폴백 조정위 두 단위, OcrService, 파서
OcrCandidateScorer두 OCR 후보를 결정적 규칙으로 비교순수 Dart
inferBeanType문구와 구성 구조로 확실/불명확 판정순수 Dart
OcrComponentDraft구성 하나의 국가·지역·가공·비율 초안 표현데이터 enum
BeanFormScreen유형 확인 결과와 구성 목록 표시, 전환·경고 처리기존 저장소/프로바이더

OcrPipeline은 UI나 데이터베이스를 알지 않는다. BeanFormScreen은 픽셀 분석과 OCR 후보 선택을 알지 않는다. 품질 분석·보정·유형 추론은 각각 가짜 구현 또는 순수 입력으로 독립 테스트할 수 있어야 한다.

5. OCR 결과 모델

OcrLine

기존 텍스트와 좌표에 ML Kit의 nullable 줄 신뢰도를 추가한다.

class OcrLine {
  final String text;
  final double left, top, right, bottom;
  final double? confidence;
}

신뢰도가 null이면 후보 비교의 신뢰도 항목에서 제외한다. null을 0점으로 취급해 정상 결과를 낮게 평가하지 않는다.

OcrComponentDraft

class OcrComponentDraft {
  final String? country;
  final String? region;
  final Process? process;
  final int? ratioPercent;
}

국가를 놓쳤지만 구성 경계가 보이는 경우도 폼에서 보완할 수 있도록 country는 초안 단계에서 nullable이다. 저장할 때는 국가가 비어 있는 초안 행을 제외하므로 ComponentInput.country와 DB의 국가 필수 규칙은 바꾸지 않는다. 싱글은 지금처럼 국가가 있는 구성 1개를 필수로 하고, 블렌드는 로스터리가 구성을 공개하지 않은 경우를 기록할 수 있도록 구성 0~N개를 허용한다.

유형 판정

enum OcrTypeDecision { certainSingle, certainBlend, ambiguous }

enum OcrTypeReason {
  explicitSingle,
  explicitBlend,
  multipleComponents,
  conflictingSignals,
  insufficientEvidence,
}

OcrDraft는 기존 단일 country/region/process 대신 List<OcrComponentDraft> components, OcrTypeDecision typeDecision, Set<OcrTypeReason> typeReasons를 가진다. 제품명·로스터리·로스팅·컵노트·칩은 현재 구조를 유지한다.

6. 사진 입력과 품질 분석

입력 품질

PhotoService.pick은 imageQuality: 85를 제거해 원본/최대 품질의 임시 파일을 받는다. ML Kit에는 이 파일을 그대로 첫 입력으로 전달한다. 저장 시에는 기존 저장 용량 성격을 유지하도록 디코드 가능한 컬러 사진을 JPEG 품질 85로 인코딩하고, OCR 보정본은 저장하지 않는다. HEIC 등 이미지 처리기가 디코드하지 못하는 형식은 저장 자체를 실패시키지 않고 원본 컬러 파일을 그대로 복사한다. 즉 OCR은 최대 품질 입력을 쓰되 일반적인 JPEG/PNG 사진은 기존과 비슷한 저장 용량을 유지한다.

분석 사본

품질 분석은 긴 변이 1024px인 방향 보정 회색조 사본에서 수행한다. 이 크기로 정규화해 해상도에 따른 지표 편차와 메모리 사용을 줄인다. 디코드·축소·지표 계산은 isolate에서 실행해 Flutter UI 스레드를 막지 않는다.

ImageQualityReport는 최소한 다음을 제공한다.

  • lowContrast: 밝기 분포가 좁아 글자/배경 분리가 약함
  • blurry: 정규화 이미지의 에지 분산이 낮음
  • strongHighlights: 밝은 픽셀이 넓은 영역에 뭉쳐 있음
  • issues: 위 문제의 집합

지표는 재촬영을 강제하지 않는다. 품질 문제가 있어도 OCR 결과가 충분하면 경고를 표시하지 않는다. 흰색 카드처럼 밝은 영역이 정상 배경인 사진에서 불필요한 경고를 피하기 위해 issues가 있고 OCR 결과도 약할 때만 품질 경고를 노출한다.

여기서 약한 OCR 결과는 최종 후보가 다음 중 하나를 만족하는 경우다: 제품명 누락, 국가가 있는 구성 없음, 비어 있지 않은 줄 4개 미만, 또는 nullable이 아닌 줄 신뢰도 평균 0.65 미만. 모든 줄 신뢰도가 null이면 마지막 조건만 제외한다.

7. 조건부 2단계 OCR

첫 단계

컬러 원본을 현재 한국어 ML Kit recognizer로 인식하고 parseOcr로 구조화한다.

두 번째 OCR 실행 조건

다음 중 하나면 보정 사본을 만들어 정확히 한 번 더 인식한다.

  • quality.lowContrast == true
  • 첫 초안에 제품명이 없음
  • 첫 초안에 국가가 있는 구성이 하나도 없음
  • 비어 있지 않은 OCR 줄이 4개 미만
  • nullable이 아닌 줄 신뢰도의 평균이 0.65 미만

모든 줄 신뢰도가 null이면 신뢰도 조건만 건너뛴다. 유형이 불명확하다는 이유만으로 두 번째 OCR을 실행하지 않는다. 카드 자체에 유형 단서가 없을 수 있기 때문이다.

보정 사본

보정은 다음 순서로 적용한다.

  1. EXIF 방향을 픽셀에 반영한다.
  2. 회색조로 변환한다.
  3. 히스토그램 양 끝 1.5%를 클리핑해 전체 명암 범위를 확장한다.
  4. 대비 계수 1.2를 적용한다.
  5. 무손실 PNG 임시 파일로 저장한다.

강한 흑백 이진화와 색상 반전은 적용하지 않는다. 컬러 카드나 얇은 글자의 획을 없앨 위험이 크고, 이번 범위의 한 번짜리 보정 사본보다 복잡한 다중 후보를 만들기 때문이다.

후보 순위

원본과 보정본 후보는 다음 튜플을 앞 항목부터 사전식으로 비교한다.

  1. 필수 항목 수: 제품명 존재, 국가가 있는 구성 존재 — 0~2
  2. 국가가 있는 구성 수
  3. 전체 구조화 필드 수: 스칼라 필드와 구성별 비어 있지 않은 필드의 합
  4. 알려진 라벨 줄 수
  5. 두 후보 모두 신뢰도 값이 하나 이상 있을 때 nullable이 아닌 줄 신뢰도의 평균
  6. 위 항목이 모두 같으면 원본 후보 우선

한 후보라도 신뢰도 값이 전혀 없으면 5번 비교는 건너뛴다. 상위 후보를 주 결과로 사용한다. 하위 후보는 주 결과의 null/빈 스칼라 필드만 채운다. 서로 다른 비어 있지 않은 값은 덮어쓰지 않는다. 구성 목록은 섞지 않고, 국가가 있는 구성 수가 더 많은 후보의 목록을 통째로 사용한다. 동수면 주 후보 목록을 사용한다. 칩은 주 후보 순서를 유지하면서 하위 후보의 새 텍스트만 뒤에 중복 제거해 추가한다.

8. 블렌드 구성 추출과 유형 판별

구성 추출

기존 국가 사전에서 첫 일치만 찾는 대신 모든 국가 출현을 좌표와 텍스트 순서대로 수집한다. 각 국가 출현을 구성 앵커로 보고 다음 정보를 결합한다.

  • 같은 행 또는 같은 열의 지역/Region, 가공/Process, 비율/Ratio 라벨 값
  • 국가와 같은 줄에 있는 % 값
  • 반복되는 원산지 표에서 다음 국가 앵커 전까지의 가까운 지역·가공·비율 값
  • 한 줄에 Brazil 50% / Ethiopia 50%처럼 여러 국가와 비율이 있으면 텍스트 출현 순서대로 짝지음

동일한 OCR 줄과 좌표에서 나온 동일 국가 중복은 하나로 합친다. 서로 다른 행·열 또는 다른 인라인 구간의 출현은 같은 국가라도 별도 구성으로 유지한다. 로스터리 주소나 설명문에 우연히 나온 국가를 구성으로 늘리는 것을 막기 위해, 두 번째 이후 구성은 다음 중 하나를 만족해야 한다.

  • % 비율이 함께 있음
  • 원산지/Origin/구성/Component/블렌드/Blend 영역 안에 있음
  • 다른 국가 앵커와 동일한 반복 행·열 패턴을 이룸

이 조건을 만족하지 않는 추가 국가 텍스트는 칩에는 남지만 구조화 구성으로 채택하지 않는다.

확정 규칙

  • 정규화된 독립 단어 blend, 블렌드, house blend가 있으면 certainBlend
  • 구조적으로 유효한 구성 앵커가 2개 이상이면 certainBlend
  • 정규화된 single origin, single-origin, 싱글 오리진이 있고 유효 구성 앵커가 1개 이하이면 certainSingle
  • 싱글 명시와 블렌드 명시가 함께 있으면 ambiguous
  • 싱글 명시와 구성 2개 이상이 충돌하면 ambiguous
  • 명시 문구가 없고 유효 구성이 0~1개이면 ambiguous

부분 문자열 오판을 막기 위해 유형 문구는 단어 경계와 공백·하이픈 정규화를 거친다. 제품명 속 일반적인 single 한 단어만으로는 싱글을 확정하지 않는다.

9. 폼과 경고 UX

폼 진입 전

  • certainSingle과 certainBlend: 확인 없이 해당 유형으로 폼 진입
  • ambiguous: 원두 유형을 확인해 주세요 다이얼로그에서 싱글 또는 블렌드 선택
  • 품질 경고가 필요하면 유형 다이얼로그보다 먼저 다시 촬영 / 인식 결과로 계속 표시
  • 재촬영은 사진 선택부터 파이프라인을 다시 시작하고, 이전 임시 보정본과 OCR 결과를 폐기

폼 내부

  • OCR로 자동 설정한 유형과 필드는 OCR 자동을 표시한다.
  • 싱글은 첫 구성만 표시한다.
  • 블렌드는 인식한 모든 구성과, 구성 수가 2개 미만이면 필요한 빈 행을 추가해 최소 2행을 표시한다.
  • 국가가 채워진 구성이 2개 미만인 블렌드는 다음 인라인 배너를 표시한다.
블렌드 구성 정보를 충분히 읽지 못했어요. 아는 내용만 입력해도 저장할 수 있어요.
  • 이 배너는 저장을 막지 않으며 별도 저장 확인 다이얼로그를 중복 표시하지 않는다.
  • 저장 검증은 싱글과 블렌드를 구분한다. 싱글은 제품명 + 첫 국가가 필수이고, 블렌드는 제품명만 필수다. 블렌드의 빈 구성 행은 저장 입력에서 제외되므로 국가가 하나도 공개되지 않은 블렌드도 구성 0개로 저장할 수 있다.
  • 싱글→블렌드 변경은 기존 첫 구성을 보존하고, 2행이 될 때까지 빈 구성을 추가한다.
  • 블렌드→싱글 변경 시 비어 있지 않은 구성이 2개 이상이면 첫 번째 구성만 남아요 확인을 표시한다. 취소하면 블렌드를 유지하고, 확인하면 첫 구성만 남긴다.
  • 직접 입력과 기존 원두 편집은 사진 품질 파이프라인을 거치지 않는다. 기존 편집 폼의 유형 전환 안전성에는 같은 구성 보존 규칙을 적용한다.

10. 오류 처리와 자원 정리

  • 품질 분석 실패: 빈 ImageQualityReport로 간주하고 원본 OCR 진행
  • 보정 생성 실패: 원본 OCR 결과 사용
  • 저장용 JPEG 인코딩 실패 또는 미지원 형식: 원본 컬러 파일 복사
  • 두 번째 OCR 실패: 원본 OCR 결과 사용
  • 원본 OCR 실패 후 보정 OCR 성공: 보정 결과 사용
  • 두 OCR 모두 실패: 빈 초안과 기존 자동 인식 실패 안내로 수동 입력 허용
  • 유형 판별 불가: 추측하지 않고 유형 확인
  • 보정 임시 파일: finally에서 삭제; 삭제 실패는 사용자 흐름을 실패시키지 않음
  • 사용자가 재촬영 또는 취소: 해당 시도의 보정 파일과 분석 결과 폐기
  • 사용자가 폼에서 수정한 값: 이후 자동 분석이나 유형 재판정으로 덮어쓰지 않음

11. 테스트와 완료 기준

유닛 테스트

  • 품질 분석: 정상 밝기, 저대비, 흐림, 강한 하이라이트 픽스처의 문제 플래그
  • 보정: 방향 반영, 회색조, 히스토그램 확장, PNG 생성, 원본 불변, 임시 파일 정리
  • 사진 저장: JPEG 품질 85 인코딩과 미지원 형식 원본 복사 폴백
  • 재시도 조건: 저대비, 제품명 누락, 국가 누락, 4줄 미만, 평균 신뢰도 0.65 미만, 전부 null인 신뢰도
  • 후보 순위와 보완: 튜플 우선순위, 충돌 값 비덮어쓰기, 구성 목록 단위 선택, 칩 중복 제거
  • 유형: 명시적 싱글/블렌드, 2개 이상 구성, 신호 없음, 상충 신호, 부분 문자열 오판 방지
  • 구성: 반복 행, 반복 열, 인라인 국가+비율, 같은 국가의 별도 구성, 설명문 국가 오탐 방지
  • 모든 분석·보정·OCR 실패 폴백

위젯 테스트

  • 확실한 유형은 확인창 없이 폼 진입
  • 불명확할 때만 유형 확인창 표시
  • 품질과 OCR이 모두 약할 때만 다시 촬영 / 계속 표시
  • 재촬영 후 새 결과만 사용
  • 블렌드 구성별 프리필과 불완전 구성 배너
  • 불완전 블렌드 저장 허용
  • 구성 0개 블렌드 저장 후 목록·상세 화면이 정상 표시되고 originLabel == null인 경로
  • 싱글↔블렌드 전환 시 행 추가·삭제 확인·취소
  • 직접 입력 흐름 비회귀

ML Kit 통합 테스트

  • 기존 ocr_card_ko.png와 ocr_card_orig.png의 8개 필드 비회귀
  • 합성 밝은 블렌드 카드: 문구형과 복수 구성형 모두 certainBlend, 구성 2개 이상
  • 합성 저대비 카드: 두 번째 OCR 실행, 원본보다 높은 후보 선택, 필수 필드 복원
  • 합성 흐림·반사 카드: 두 후보가 약하면 품질 경고 조건 충족

합성 픽스처만 공개 저장소에 커밋한다. 실제 상용 카드 사진은 사용자가 명시적으로 허용하지 않는 한 커밋하지 않고 로컬/실기기 검증에만 사용한다.

실기기 완료 기준

  • Blend/블렌드 명시 카드가 질문 없이 블렌드 폼을 연다.
  • 명시 없이 구성 2개 이상인 카드가 질문 없이 블렌드 폼을 연다.
  • 단서가 없거나 충돌하는 카드는 유형을 정확히 한 번 확인한다.
  • 구성별 국가·지역·가공·비율이 다른 행으로 배치된다.
  • 어두운 저대비 카드에서 보정 후보가 원본보다 더 많은 유효 필드를 채운다.
  • 심한 흐림·반사 사진은 재촬영을 권하지만 계속 진행할 수 있다.
  • 밝은 기존 카드에서는 두 번째 OCR을 불필요하게 실행하지 않고 기존 8개 필드를 유지한다.
  • 분석·보정 실패를 강제로 발생시켜도 앱이 멈추지 않고 원본 OCR 또는 수동 입력으로 진행한다.
