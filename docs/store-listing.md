# App Store 스토어 페이지 입력값

App Store Connect의 각 칸에 그대로 붙여넣는다. 글자 수는
`python scripts/check_store_listing.py`로 검증한다(초과하면 입력이 거부된다).

작성 기준 세 가지:

- **"개인용"이라고 쓰지 않는다.** 심사 가이드라인 4.2는 일반 사용자에게 쓸모가 있는지를 본다. 실제로 쓸모가 있으므로 그렇게 쓰면 될 뿐, 스스로를 취미 프로젝트로 소개할 이유가 없다.
- **하지 않는 일을 적지 않는다.** 동기화·공유·추천 기능이 없으므로 언급하지 않는다.
- **비교·최상급을 피한다.** "최고의", "유일한" 같은 표현은 근거를 요구받을 수 있다.

```
봉투 사진 한 장이면 원두 정보가 자동으로 채워집니다. 기록이 쌓이면 어떤 산지와 어떤 향을 좋아하는지 앱이 정리해 보여줍니다. 계정도 인터넷 연결도 필요 없습니다.
```

## 설명 (4000자)

```
좋았던 원두를 다시 찾지 못한 적이 있다면

마신 커피를 기록해 두려다 봉투에 적힌 정보를 옮겨 적는 게 번거로워 포기한 적이 있을 겁니다. BeanProfile은 그 옮겨 적는 일을 대신합니다. 원두 봉투나 정보 카드를 찍으면 제품명, 로스터리, 원산지, 가공 방식, 로스팅 날짜, 컵노트를 읽어 입력란을 채웁니다. 잘못 읽은 부분만 고치면 됩니다.


■ 사진 한 장으로 시작하는 기록

카메라로 찍거나 갤러리에서 고르면 글자를 인식해 항목별로 나눠 담습니다. 인식이 애매한 단어는 칩으로 보여주고, 원하는 칸에 직접 배정할 수 있습니다. 여러 칩을 이어 붙여 하나의 값으로 만들 수도 있습니다. 블렌드는 구성 원두와 비율까지 나눠 기록합니다.


■ 마실 때마다 남기는 네 가지 강도와 별점

산미, 단맛, 바디, 쓴맛을 1~5로 고르고 종합 별점과 한 줄 코멘트를 남깁니다. 같은 원두라도 추출을 바꾸면 맛이 달라지므로, 한 원두에 여러 번의 기록을 쌓을 수 있습니다.


■ 로스팅 후 며칠째인지 함께 기록

로스팅 날짜를 넣어두면 각 시음이 로스팅 후 며칠째였는지 자동으로 계산해 보여줍니다. 며칠째가 가장 좋았는지 눈으로 확인할 수 있습니다.


■ 쌓인 기록이 알려주는 내 취향

기록이 모이면 선호 강도를 도형으로, 원산지별 평균 평점과 자주 좋았던 컵노트를 막대로 정리해 보여줍니다. 어떤 지역과 어떤 향을 좋아하는지, 외부 평가가 아니라 직접 남긴 기록만으로 드러납니다.


■ 찾기와 정리

원두 이름과 로스터리로 검색하고, 최근순·이름순·평점순으로 정렬합니다.


■ 기록은 기기 안에만 남습니다

계정을 만들 필요가 없고, 로그인 화면도 없습니다. 사진과 기록은 기기 밖으로 나가지 않으며 광고도 없습니다. 비행기 안에서도, 지하에서도 그대로 동작합니다.

기기를 바꾸거나 백업이 필요할 때는 설정에서 기록 전체를 파일 하나로 내보낼 수 있습니다. 사진도 함께 담기며, 같은 파일로 되돌릴 수 있습니다.


■ 이런 분들께

· 스페셜티 원두를 자주 바꿔가며 마시는 분
· 같은 원두를 추출을 바꿔가며 비교하는 분
· 마음에 들었던 원두를 다시 사고 싶은 분
· 내 취향이 어느 쪽인지 정리해 보고 싶은 분
```

## 새로운 기능 (4000자)

App Store Connect는 이 칸을 **업데이트에만** 요구한다. 첫 출시에서는 필드가
아예 나타나지 않는다 — 사용자에게는 앱 전체가 처음이라 "무엇이 바뀌었는지"를
쓸 대상이 없기 때문이다.

첫 출시인데 칸이 보인다면 변경점 대신 앱을 소개한다.

```

원두 봉투나 정보 카드를 찍으면 제품명, 로스터리, 원산지, 가공 방식, 로스팅 날짜, 컵노트를 읽어 입력란을 채웁니다. 마실 때마다 산미·단맛·바디·쓴맛과 별점을 남기면, 기록이 쌓이는 대로 어떤 산지와 어떤 향을 좋아하는지 정리해 보여줍니다.

기록은 기기 안에만 저장됩니다. 계정도 인터넷 연결도 필요 없습니다.
```

## 개인정보 보호 (App Privacy)

**"예, 이 앱에서 데이터를 수집합니다"** 를 고르고 아래 네 유형을 신고한다. 개발자는 아무것도 받지 않지만, 문자 인식에 쓰는 Google ML Kit이 진단 데이터를 Google로 보내고, Apple은 앱에 들어간 SDK가 보내는 데이터도 앱의 수집으로 본다. 무엇을 보내는지는 [`privacy.md`](privacy.md)의 「Google ML Kit이 보내는 진단 정보」에 있다.

| 데이터 유형 | 목적 | 사용자에게 연결됨 | 추적 |
|---|---|---|---|
| 식별자 › 기기 ID (Identifiers › Device ID) | 분석 | 아니요 | 아니요 |
| 사용 데이터 › 제품 상호 작용 (Usage Data › Product Interaction) | 분석 | 아니요 | 아니요 |
| 진단 › 성능 데이터 (Diagnostics › Performance Data) | 분석 | 아니요 | 아니요 |
| 진단 › 기타 진단 데이터 (Diagnostics › Other Diagnostic Data) | 분석 | 아니요 | 아니요 |

Google의 [ML Kit iOS 데이터 공개 안내](https://developers.google.com/ml-kit/ios-data-disclosure)는 보내는 데이터만 나열하고 Apple 범주는 정해주지 않는다(2026-10-04 원문 확인). 위 매핑은 우리 판단이다 — 설치 단위 식별자는 기기 ID, 지연 시간은 성능 데이터, 기기·앱 정보와 API 설정·오류 코드는 기타 진단 데이터, 기능 이벤트(초기화·인식)는 제품 상호 작용. **애매하면 넓게 신고한다** — 적게 신고한 라벨은 정책 위반이지만 넓게 신고한 라벨은 아니다. 사진과 입력 내용은 여전히 기기를 벗어나지 않으므로 사진·사용자 콘텐츠 유형은 신고하지 않는다.

라벨은 App Store Connect → 앱 개인정보 보호에서 **새 버전 제출 없이** 고칠 수 있다.

## Google Play 데이터 보안 (Data safety)

> 2026-10-07 — Android는 GitHub Release의 APK를 직접 설치하는 방식으로 바꿨다. 이 절은 나중에 Play로 출시할 때 쓴다.

Play Console → 정책 및 프로그램 → 앱 콘텐츠 → 데이터 보안. 근거는 바로 위 App Store 라벨과 같고, 범주도 같은 원칙으로 맞췄다 — 두 스토어가 같은 사실을 같은 넓이로 신고한다. 출처: [ML Kit Android 데이터 공개 안내](https://developers.google.com/ml-kit/android-data-disclosure)(전송 중 HTTPS 암호화, 제3자 이전 없음).

| 질문 | 답 |
|---|---|
| 앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요? | 예 |
| 앱에서 수집하는 모든 사용자 데이터가 전송 중에 암호화되나요? | 예 — ML Kit은 HTTPS로 보내고, 앱 자체는 아무것도 보내지 않는다 |
| 사용자가 데이터 삭제를 요청할 방법을 제공하나요? | 아니요 — 개발자가 받는 데이터가 없다 |

수집하는 데이터 유형 — 세 유형 모두 답이 같다.

| 데이터 유형 | 수집 / 공유 | 일시적으로 처리 | 수집 필수 여부 | 목적 |
|---|---|---|---|---|
| 기기 또는 기타 ID (Device or other IDs) | 수집함 / 공유 안 함 | 아니요 | 필수(사용자가 끌 수 없음) | 분석 |
| 앱 활동 › 앱 상호작용 (App interactions) | 수집함 / 공유 안 함 | 아니요 | 필수 | 분석 |
| 앱 정보 및 성능 › 진단 (Diagnostics) | 수집함 / 공유 안 함 | 아니요 | 필수 | 분석 |

사진·기록·인식된 글자는 기기를 벗어나지 않으므로 사진 및 동영상, 파일 및 문서 같은 유형은 신고하지 않는다.

## 심사 메모 (App Review Notes)

리뷰어가 막힐 만한 지점을 미리 없앤다.

```
This app works fully offline. No account or login is required — the reviewer can use every feature immediately after launch.

Text recognition runs on-device (ML Kit). To try it: tap + on the bean list, choose 촬영 or 갤러리, and select any photo containing printed text such as a coffee bag or a printed card. Recognized text is offered as chips that can be assigned to fields; all fields can also be typed manually if no suitable photo is available.

The taste dashboard (second tab) fills in once at least one tasting is recorded.

Photos, records, and recognized text never leave the device. There is no account, no developer-run server, no advertising, and no tracking. Google ML Kit itself sends technical diagnostics (device and app information, performance metrics) to Google; this is declared in the app's privacy label.
```
