iOS OCR 진단 복사 설계

목적

동일한 C 카드가 Android 에뮬레이터에서는 정상 파싱되지만 iPhone 직접 촬영에서는 구성 필드가 누락되는 원인을 확인한다. 추측성 파서 수정을 반복하지 않도록 iPhone의 실제 ML Kit 출력과 파이프라인 판정 결과를 사용자가 클립보드로 복사해 전달할 수 있게 한다.

범위

  • 사진 OCR로 진입한 원두 입력 화면에만 OCR 진단 복사 버튼을 표시한다.
  • 버튼을 누를 때 원본 사진과 대비 보정본을 각각 강제로 OCR 분석한다.
  • 분석 결과를 사람이 읽을 수 있는 일반 텍스트로 만들어 클립보드에 복사한다.
  • 진단 결과는 DB, 원두 메모, 로그 파일에 저장하지 않는다.
  • 일반 사진 OCR 흐름과 저장 데이터 형식은 변경하지 않는다.

진단 버튼은 iOS 원인 확인을 위한 임시 도구다. 필요한 실기기 자료를 확보하고 수정이 검증되면 후속 버전에서 제거한다.

사용자 흐름

  1. 사용자가 촬영 또는 갤러리 사진으로 OCR을 실행한다.
  2. 원두 입력 화면에서 OCR 진단 복사를 누른다.
  3. 버튼이 비활성화되고 진행 표시가 나타난다.
  4. 앱이 현재 사진을 원본과 대비 보정본으로 각각 재분석한다.
  5. 성공하면 진단 텍스트를 클립보드에 복사하고 OCR 진단 정보가 복사됐어요 메시지를 표시한다.
  6. 사용자는 이 대화에 클립보드 내용을 그대로 붙여넣는다.

직접 입력·기존 원두 편집처럼 OCR 사진 임시 경로가 없는 화면에는 버튼을 표시하지 않는다.

구조

OcrDiagnosticsService

일반 OcrPipeline과 분리된 일회성 진단 서비스다. OcrService, ImageQualityAnalyzer, OcrImagePreprocessor를 주입받는다.

서비스는 다음 작업만 담당한다.

  • 원본 이미지 품질 분석
  • 원본 OCR 라인과 파싱 후보 생성
  • 대비 보정 이미지 생성
  • 보정본 OCR 라인과 파싱 후보 생성
  • 일반 파이프라인과 같은 비교·병합 규칙으로 최종 후보 계산
  • 임시 보정 이미지 정리
  • 진단 보고서 생성

일반 OCR 처리에는 이 서비스가 호출되지 않으므로 평상시 촬영 시간은 늘어나지 않는다.

OcrDiagnosticsReport

진단 결과를 보관하고 toClipboardText()로 안정적인 텍스트 형식을 만든다. UI가 OCR 내부 객체를 직접 포맷하지 않게 한다.

보고서에는 다음 정보가 포함된다.

  • 진단 형식 버전
  • 실행 플랫폼
  • 원본 이미지의 디코딩 크기와 EXIF 방향 값(읽을 수 있는 경우)
  • 이미지 품질 이슈
  • 원본·보정본의 후보 점수 정보
  • 원본·보정본 OCR 라인: 텍스트, bounding box, 신뢰도
  • 원본·보정본 파싱 결과
  • 선택된 후보와 최종 병합 결과

사진 바이트, 로컬 파일 경로, 기기 식별자와 계정 정보는 포함하지 않는다.

화면 연결

BeanFormScreen은 기존 photoTempPath가 있고 OCR 초안으로 열린 경우에만 진단 버튼을 노출한다. 버튼은 Provider를 통해 진단 서비스를 호출하고 Flutter의 Clipboard API로 텍스트를 복사한다.

진단 실행 상태는 화면 내부의 단일 불리언으로 관리한다. 실행 중 중복 탭을 막고, 화면이 닫힌 뒤에는 메시지나 상태 변경을 시도하지 않는다.

진단 텍스트 형식

각 섹션은 고정 헤더를 사용해 붙여넣은 결과를 회귀 테스트 픽스처로 옮기기 쉽게 한다.

=== BEANPROFILE OCR DIAGNOSTICS v1 ===
platform: ios
image: 3024x4032, exifOrientation=6
quality: lowContrast, blurry

--- ORIGINAL ---
candidate: ...
[left,top,right,bottom] confidence | text
...
draft:
  component[0]: country=... ratio=... region=... process=...

--- ENHANCED ---
...

--- FINAL ---
selected: original
component[0]: ...
component[1]: ...

OCR 텍스트는 한 줄 단위로 기록한다. confidence가 제공되지 않으면 null로 출력한다. 좌표는 비교가 쉽도록 소수점 한 자리까지 출력한다.

오류 처리

  • 품질 분석 실패: 빈 품질 결과로 계속 진행하고 보고서에 실패 상태를 기록한다.
  • 보정 또는 보정본 OCR 실패: 원본 결과는 유지하고 보정 실패를 보고서에 기록한다.
  • 클립보드 복사 실패: 폼을 유지하고 오류 메시지를 표시한다.
  • 임시 보정 이미지 삭제 실패: 진단 결과를 버리지는 않지만 보고서에 정리 실패를 기록한다.
  • 중복 탭: 실행 중 버튼 비활성화로 차단한다.

테스트

단위 테스트

  • 원본과 보정본을 항상 한 번씩 분석한다.
  • 후보 비교·병합 결과가 일반 파이프라인과 일치한다.
  • 보정 실패 시에도 원본 보고서를 만든다.
  • 임시 보정 이미지를 성공·실패 경로 모두에서 정리한다.
  • 보고서 텍스트가 좌표, 신뢰도, 품질, 후보, 최종 구성 정보를 포함한다.
  • 보고서가 읽을 수 있는 이미지 크기와 EXIF 방향 값을 포함한다.
  • 보고서에 이미지 경로나 사진 바이트가 포함되지 않는다.

위젯 테스트

  • OCR 사진이 있는 폼에서만 진단 버튼이 보인다.
  • 버튼 탭 시 중복 실행이 차단되고 성공 후 클립보드 안내가 표시된다.
  • 서비스 실패 시 폼을 유지하고 오류 안내가 표시된다.

완료 조건

  • 일반 OCR 처리 시간과 저장 데이터에 변화가 없다.
  • iPhone에서 버튼 한 번으로 원본·보정 OCR 좌표와 최종 매핑을 전달할 수 있다.
  • 전달된 텍스트만으로 iOS 실패를 호스트 단위 테스트에 재현할 수 있다.
